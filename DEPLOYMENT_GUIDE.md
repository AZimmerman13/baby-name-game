## 🏗️ Initial Server Setup (One-Time)

Run this **ONCE** when setting up a new server.

### Prerequisites

- A Digital Ocean droplet (or any VPS) running Ubuntu
- SSH access to the server
- Domain name pointing to your server IP

### Step 1: Copy Setup Script to Server

```bash
# From your local machine
scp setup-production-server.sh root@storkpool.com:/root/
```

### Step 2: Run Setup Script on Server

```bash
# SSH to your server
ssh root@storkpool.com

# Run the setup script
sudo bash /root/setup-production-server.sh
```

This script will:
- ✅ Add 2GB swap space (prevents OOM during builds)
- ✅ Install Docker and Docker Compose
- ✅ Clone the repository to `/opt/baby-name-game`
- ✅ Generate secure environment variables
- ✅ Create data directories
- ✅ Configure firewall
- ✅ Set up automatic Docker cleanup

### Step 3: Initial Deployment

```bash
# Still on the server
cd /opt/baby-name-game
docker-compose up -d --build

# Check logs
docker-compose logs -f
```

### Step 4: Configure SSL with Auto-Renewal

```bash
# Run the SSL setup script (handles everything automatically)
sudo bash /opt/baby-name-game/setup-ssl-renewal.sh
```

This script will:
- ✅ Obtain SSL certificates using webroot method (zero downtime)
- ✅ Configure automatic renewal (checks every 12 hours)
- ✅ Test the renewal process
- ✅ Reload nginx with new certificates

**Important:** This replaces the old manual `certbot --standalone` method which required manual renewal.

## 🔧 Troubleshooting

### Build Fails with "Out of Memory"

The setup script should have added swap space. Verify:

```bash
ssh root@storkpool.com
free -h  # Should show 2G swap

# If no swap, add it manually:
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Services Won't Start

Check logs:

```bash
ssh root@storkpool.com
cd /opt/baby-name-game
docker-compose logs backend
docker-compose logs frontend
```

### Database Issues

View database backups:

```bash
ssh root@storkpool.com
ls -lh /opt/baby-name-game/backups/
```

Restore a backup:

```bash
cd /opt/baby-name-game
docker-compose down
cp backups/baby_name_game_YYYYMMDD_HHMMSS.db data/baby_name_game.db
docker-compose up -d
```

### Check Container Status

```bash
ssh root@storkpool.com
cd /opt/baby-name-game
docker-compose ps
```

### View Live Logs

```bash
ssh root@storkpool.com
cd /opt/baby-name-game
docker-compose logs -f
```

### Rebuild Without Cache

If you need a completely fresh build:

```bash
ssh root@storkpool.com
cd /opt/baby-name-game
docker-compose down
docker-compose build --no-cache
docker-compose up -d
```

### Check Disk Space

```bash
ssh root@storkpool.com
df -h
docker system df

# Clean up if needed
docker system prune -f --volumes
```

## 🔐 SSL Certificate Management

### Automatic Renewal

Your SSL certificates automatically renew! The certbot container checks every 12 hours and renews certificates when they're within 30 days of expiration.

**No manual intervention required** - renewals happen automatically with zero downtime.

### Initial Setup (If You Used Manual Method)

If you previously got certificates with `certbot --standalone`, you need to switch to the automated method:

```bash
ssh root@storkpool.com
cd /opt/baby-name-game
sudo bash setup-ssl-renewal.sh
```

This will:
1. Give you option to keep or recreate your certificate
2. Switch to webroot method (allows renewal without stopping nginx)
3. Test automatic renewal
4. Configure the certbot container

### Check Certificate Status

```bash
ssh root@storkpool.com
cd /opt/baby-name-game
docker-compose run --rm certbot certificates
```

Output shows:
- Certificate expiration date
- Domains covered
- Renewal configuration

### Manual Renewal (Testing Only)

```bash
# Dry run (test without actually renewing)
docker-compose run --rm certbot renew --dry-run

# Force renewal (only if needed for testing)
docker-compose run --rm certbot renew --force-renewal
docker-compose exec nginx nginx -s reload
```

### Troubleshooting SSL

**Problem**: Certificate not renewing automatically

**Solution**:
```bash
# Check certbot container is running
docker-compose ps certbot

# Restart certbot container
docker-compose restart certbot

# Test renewal manually
docker-compose run --rm certbot renew --dry-run
```

**Problem**: "Connection refused" during renewal

**Solution**: Make sure nginx is running and port 80 is accessible:
```bash
docker-compose ps nginx
curl http://storkpool.com/.well-known/acme-challenge/test
```
